# 体验问题清单

- 更新日期：2026-09-02
- 范围：真实用户试用中发现的流程理解、交互反馈、页面语言和视觉呈现问题。
- 与 `docs/OPEN_ISSUES.md` 的区别：本文件记录用户体验和界面层面的改进项；后者只记录技术、模型、安全、成本、部署和产品边界等待决事项。

## 使用方式

- 每条问题保留用户观察、可复现条件、当前处理状态和验证方式。
- 体验问题可以在后续讨论中调整优先级，不自动扩大为新产品能力。
- 已完成项不删除，保留为可追溯的设计反馈。

| UX-001 | 高 | 选择 PDF 后，页面仍停在导入区，用户不清楚还需要点击什么，也看不到完整精读流程。 | “已选文件”和“已完成导入”缺少明确区分；主按钮没有说明解析后会进入下一步。 | 选择文件后显示“已选择，点击解析并继续”；导入区、阅读画像、精读路线、阶段精读分别标记为步骤 1–4；导入成功后预告路线、精读和笔记流程。 | 选择文件后无需猜测下一步；导入成功后可见步骤 2，生成路线后可见步骤 3，进入阶段后可见步骤 4。 | 已修复，待用户复验 |

| UX-007 | 高 | 精读回答显示为原始 Markdown，标题、粗体、列表和代码围栏直接暴露，长文难以扫描。 | 消息此前按普通段落渲染，没有 Markdown AST 和来源标记的展示层。 | 使用 `react-markdown` + `remark-gfm`；完整响应后统一渲染，禁用原生 HTML，合法引用转换为可点击入口。 | 完整回答中的标题、列表、代码块、表格和引用均有可读样式；恶意 HTML 不执行。 | 已修复，待用户复验 |
| UX-008 | 高 | 精读内容、检查问题、路线和文档地图纵向堆叠，阅读时需要在页面中反复寻找输入区。 | 阶段工作区是路线页内联区域，缺少持续可见的对话边界和固定输入位置。 | 开始阶段前展示完整地图和路线；开始后切换到独立精读工作台，地图通过右侧可停靠标签检查器查看，输入区固定在工作台底部。 | 开始阶段后地图不再压住精读内容；地图/引用可切换；工作台输入区和下箭头保持可用。 | 已修复，待用户复验 |
| UX-009 | 中 | 用户无法持续判断“当前正在读什么、已完成什么、下一步是什么”。 | 阶段状态、路线进度和当前对话上下文分散在不同页面区域。 | 在抽屉标题和路线卡片中统一展示阶段编号、状态、进度和下一动作。 | active/awaiting_note/pending/completed 状态在桌面和移动端均可辨认，刷新后不回退到已完成阶段。 | 待实现 |
| UX-010 | 中 | 引用标记 `[S1]` 在原始 Markdown 中像普通文本，用户不能快速核对依据。 | 引用 ID 已在服务端校验，但缺少消息层的交互组件。 | 完整消息渲染时把合法引用转换为可点击来源入口；无效标记按普通文本处理并记录告警。 | 点击引用打开正确片段、页码/章节和来源元数据；不存在伪造来源按钮。 | 已修复，待用户复验 |
| UX-011 | 中 | 生成中、生成失败和完成后的视觉状态区分不够，用户可能误以为内容已保存。 | 流式 token、正式消息和笔记草稿的状态边界没有在界面上明确表达。 | 保留临时流状态，完成后才提交正式消息；错误状态保留输入并提供重试。 | 中断不会推进阶段或写入笔记；重试不会重复消息。 | 已有实现，待用户复验 |
| UX-013 | 高 | 从文档地图进入“调整画像”后没有返回能力，用户只能重新生成路线并消耗模型 token。 | 导入、画像和路线原本只是单组件内的布尔状态，浏览器历史无法表达页面切换。 | 新增 `/home`、`/profile`、`/reading` 访问路径；调整画像使用路由跳转；浏览器后退恢复既有路线且不调用模型。 | 从路线进入画像后，浏览器后退和左上返回均可恢复路线；只有提交“重新生成路线”才调用模型并重置进度。 | 已修复，待用户复验 |
| UX-014 | 高 | 左侧来源详情长期占用空间，侧栏不像可操作的工作区导航。 | 来源元数据、质量详情和标题全部常驻，且没有会话与全局入口。 | 来源标题常驻，元数据与解析质量仅在鼠标悬浮或键盘聚焦时浮层显示，并提供过渡效果。 | 默认仅显示标题；悬浮后显示完整详情；移开后收起；键盘用户可聚焦打开。 | 已修复，待用户复验 |
| UX-015 | 中 | 左侧缺少新建会话、收起展开、历史、设置和登录入口，页面整体显得未完成。 | 首版只实现了单会话主流程，没有搭建工作区导航骨架。 | 新建会话和收起展开直接可用；历史、设置、登录保留中文占位入口并明确提示后续开放。 | 新建会话生成新的临时会话；收起后只保留图标；占位入口不执行虚假业务操作。 | 已修复，待用户复验 |
| UX-016 | 中 | 用户无法通过产品标题回到首页，也不清楚返回按钮与首页入口的区别。 | 顶栏品牌原为静态元素。 | 品牌标题固定跳转 `/home`；非首页左侧显示返回按钮并执行浏览器历史返回。 | 标题始终回首页；返回按钮回到上一条有效路径。 | 已修复，待用户复验 |
| UX-017 | 高 | 右侧空白未被利用，地图和引用抽屉互相覆盖，长回答时主工作区偏移。 | 旧抽屉是覆盖式 modal，主内容宽度没有参与布局计算。 | 使用动态 `--inspector-width` 与右侧 dockable inspector；地图和引用以标签页共存，中央工作区按可用宽度居中并平滑压缩。 | 打开/关闭检查器、收起左栏时主内容保持左右留白平衡；检查器内部独立滚动。 | 已修复，待用户复验 |
| UX-018 | 高 | 对话输入框随正文下沉，无法持续追问；下箭头固定在页面右下而非对话区。 | 消息列表和控制区共享页面滚动，按钮使用 viewport fixed。 | `stage-workspace` 使用独立消息滚动区，输入区固定在工作台底部，下箭头绝对定位于工作台内部。 | 长回答后输入框仍可见；下箭头只滚动消息区，不推动主页面。 | 已修复，待用户复验 |
| UX-019 | 中 | 页面色调与产品定位不一致，品牌和重点色不够稳定。 | 旧主题使用深绿色，页眉品牌位于顶部且占用主空间。 | 采用暖原木色 `#faf8f4`，重点色改为天蓝 `#5d8dbb`；品牌 `Lumen` 移至左侧栏顶部，页眉显示当前文件名。 | 桌面、移动端颜色和品牌位置一致，文字对比度可读。 | 已修复，待用户复验 |
| UX-020 | 高 | 右侧边栏开启后直接压缩精读正文，导致标题逐字换行、操作区不可用。 | 中间工作台宽度被布局容器按剩余空间压缩，左右空白没有作为弹性变量。 | 工作台固定为 900px；主区采用居中容器，左右留白随左栏/检查器开关同步变化且保持相等。窗口不足时检查器降级为覆盖层，避免压缩工作台。 | 宽屏开关左右栏时工作台宽度不变且居中；窄桌面/移动端无水平溢出或逐字断行。 | 已修复，待用户复验 |
| UX-021 | 中 | 右侧边栏没有稳定的材料入口，引用与地图的打开顺序会改变可见内容。 | 检查器此前只有按需标签，缺少不可关闭的基础上下文。 | 第一次展开默认打开“原文预览”，并固定保留“原文预览 / 文档地图”两个标签；引用只在用户点击来源后新增，可单独关闭。 | 反复开合后基础标签仍存在；点击 `[S1]` 后可切换回原文或地图。 | 已修复，待用户复验 |

| UX-023 | 中 | 阶段导航信息占用正文空间，操作按钮分散在对话框外。 | 阶段标题、状态和操作区同时常驻主工作台。 | 当前阶段摘要迁移到左侧菜单；主工作台隐藏重复标题；输入区内只保留“下一阶段”和“追问”。 | 精读信息流获得连续阅读空间；操作区不再额外占用页面纵向区域。 | 已实现，待用户复验 |
| UX-024 | 高 | 进入笔记草稿后，完整精读对话仍显示在笔记编辑器上方，压缩了主要编辑区域。 | 阶段工作台未按 `awaiting_note` 状态切换内容职责。 | 笔记预览阶段隐藏中央消息流；新增右侧固定“精读记录”标签，展示当前阶段完整对话、Markdown 和引用入口。 | 草稿页中央只保留笔记编辑与操作；右侧标签可独立滚动查看记录。 | 已处理，待用户复验 |
| UX-025 | 高 | 点击“接受并完成阶段”没有下载文件，且接受与跳过后的页面像空白中间页。 | 接受接口只更新会话，没有触发下载；完成后仍停留在阶段工作台且没有路线交接视图。 | 接受后触发 Markdown 汇总下载；接受/跳过后返回精读路线并选中下一待开始阶段；工作区右上提供“查看精读路线”入口。 | 接受后浏览器出现 `.md` 下载；下一阶段可从路线继续；不再出现仅一个按钮的空白页。 | 已处理，待用户复验 |
| UX-026 | 高 | 全部阶段完成后缺少业务出口，只能关闭页面或点击不相关入口。 | 完成状态没有单独的终点反馈和回首页动作。 | 路线底部显示完成卡片，提供“学学别的”按钮返回 `/home`，重新进入导入闭环。 | 完成最后阶段后能看到完成反馈并一键回首页。 | 已处理，待用户复验 |
