# 技术文档精读助手需求调研

- 版本：`v0.2`
- 状态：讨论基线
- 日期：2026-09-01

## 1. 调研目标

判断“技术文档精读助手”是否比通用学习聊天机器人更适合本次面试作业，并确定一个在 1–2 个开发日内可以实现、演示和解释的产品边界。

## 2. 用户问题

目标用户是需要进入陌生技术领域的软件开发者。典型材料包括 RFC、协议规范、架构设计、原理说明和较长的官方技术文档。

真实困难不是缺少摘要，而是：

- 不知道文档解决什么问题、哪些章节应先读。
- 概念之间有依赖关系，按原文顺序阅读未必适合当前用户。
- 规范关键词、约束、例外和版本边界容易被摘要丢失。
- 通用聊天回答可能脱离原文，无法核对出处。
- 阅读过程中的理解没有沉淀，下一次仍要重新梳理。

## 3. 现有产品观察

| 产品或方向 | 公开定位中的强项 | 对本项目的启示 |
| --- | --- | --- |
| [Gemini Notebook](https://notebooklm.google/) | 基于用户来源进行分析和内容转化 | 来源约束是基础能力，不足以单独形成差异 |
| [Kapa](https://www.kapa.ai/) | 面向非结构化知识的准确问答与检索 | 开发者文档问答已有成熟产品，不能只做聊天框 |

| [DocsBot](https://docsbot.ai/) | 基于业务知识的问答和自动化 | 客服/知识机器人侧重回答，精读过程仍有空间 |

## 4. 产品机会

首版不定位为“问文档任何问题”，而定位为：

> 根据开发者的阅读目标和熟悉程度，把一份技术规范转换成可执行的精读路线；每个阶段基于原文解释机制和约束，并把用户确认过的内容沉淀为可追溯笔记。

差异化由四个连续行为组成：

1. **阅读适配**：由阅读目标和熟悉程度决定路线，而不是机械按目录总结。
2. **机制拆解**：突出概念依赖、数据流、约束、例外和落地含义。
3. **可信引用**：所有原文事实可定位，证据不足时明确说明。
4. **确认式沉淀**：AI 只提出笔记草稿，用户确认后才成为成果。

## 5. 已确认产品决定

- 首版用户：软件开发者。
- 首要材料：RFC、架构设计和原理/规范类长文档。
- 输入：文件上传与用户指定的公开 URL 并重。
- 联网边界：只读取用户提供的 URL，不主动搜索其他网页。
- 无文档状态：不提供通用聊天。
- 路线生成：由阅读目标和熟悉程度驱动。
- 来源体验：引用定位抽屉，不实现长期全文分屏。
- 笔记：每阶段生成可编辑草稿，接受后累积并导出 Markdown。
- 输出语言：中文解释，保留英文术语、规范关键词和代码原文。
- 模型基线：用户提供的 OpenAI-compatible Qwen API，默认 `qwen3.6-flash`。
- 检索基线：本地章节/关键词检索，Embedding 作为可选扩展。
- 响应方式：结构化结果非流式，较长阶段讲解流式。
- 实现目标：1–2 个完整开发日的在线演示版。
- 演示材料：优先 RFC 6455 或获准使用的 MyBatis 事务规范；其他材料用于格式、规模和降级回归。

## 6. 场景与任务拆解

### 场景 A：建立整体认知

开发者第一次阅读协议或架构文档，希望先理解问题背景、核心参与者、机制链路和章节关系，再决定精读位置。

### 场景 B：理解关键机制

开发者针对握手、状态机、一致性、缓存等机制进入阶段精读，通过原文引用、示例和检查问题验证理解。

### 场景 C：为实现或评审做准备

开发者需要提取规范关键词、前置条件、异常分支、安全约束和落地风险，形成可复用的评审笔记。

## 7. 原型验证假设

| 假设 | 验证方式 | 通过标准 |
| --- | --- | --- |
| 阅读画像能改变路线 | 同一文档使用不同目标和熟悉程度生成路线 | 阶段重点和解释深度存在可说明差异 |
| 路线比一次摘要更有价值 | 让测试者分别查看摘要与阶段路线 | 测试者能指出下一步应该读什么及原因 |
| 引用能提升可信度 | 对预置问题逐条核对来源 | 所有展示引用均可定位到真实片段 |
| 确认式笔记能避免错误沉淀 | 修改、跳过和接受不同草稿 | 导出只包含用户接受后的文本 |

## 8. 调研限制与 P1 补充

- 已取得并验证用户允许测试的混合格式材料；MyBatis 规范适合作为约束型主 Demo，RFC 6455 适合作为公开交叉回归，详细结果见 `docs/reports/P1_VALIDATION.md`。
- 本阶段没有进行真实用户访谈，痛点依据开发者工作流和竞品观察形成。
- 首版不能证明长期学习或工作效率提升，只验证阅读流程是否更清晰、结果是否可追溯。
