# P4 阶段交接：分阶段精读工作流

- 日期：2026-09-02
- 状态：已完成
- 下一阶段：P5 确认式笔记与导出

## 解决的业务问题

用户可以逐阶段获取基于当前文档证据的流式讲解，并继续追问、回答理解检查或请求换一种解释。讲解完整结束后才写入会话；用户主动结束阶段后进入待确认笔记状态。

## 已锁定约定

- 同时只能有一个活动阶段和一个上游流式请求。
- token 只是浏览器临时状态；`complete` 前不保存用户消息、助手消息或阶段状态。
- 模型只看到本轮本地检索的 5 个来源片段；未知引用 ID 被丢弃。
- 没有有效引用时完整内容仍可显示，但明确标记证据不足。
- 理解检查使用稳定的阶段目标模板，模型负责对答案反馈。
- `finish` 只进入 `awaiting_note`，P5 接受或跳过后才 `completed`。

## 数据流与失败表现

```text
阶段动作 -> 状态校验/流锁 -> 本地检索 -> Qwen SSE -> 浏览器临时 delta
  -> 正常结束：引用过滤 + 原子提交
  -> 中断：释放流锁 + 丢弃临时状态 + 保留用户输入以重试
```

## 验证结果

- 12 个测试文件、48 项测试通过。
- 中间 token 后抛错的自动化测试证明消息和 `pending` 状态保持不变。
- 未知 `[S99]` 引用被过滤，只有当前来源 ID 进入会话视图。
- TypeScript 与 Next.js 生产构建通过。
- 真实 MyBatis 首阶段：首事件 0.79 秒，总计 7.61 秒，373 个 delta、2,210 字符、5 个有效引用。
- 完整事件后状态为 `active`、消息数为 1；结束后状态为 `awaiting_note`，未提前完成。

## P5 依赖

P5 只能为 `awaiting_note` 阶段创建一个待处理草稿。接受和跳过必须幂等，只有接受后的内容进入导出；P5 不得重新解释或修改 P4 已保存的消息。
