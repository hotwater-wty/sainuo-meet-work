# P1 技术可行性验证报告

- 版本：`v0.2`
- 日期：2026-09-02
- 结论：通过，允许进入 P2；URL 网关需在实际部署网络补一次端到端验证
- 模型基线：`qwen3.6-flash`（OpenAI-compatible）

## 1. 验证范围

P1 在不创建业务 UI 的前提下验证了六项高风险能力：本地 PDF/Markdown 解析、RFC 6455 HTML 导入、解析质量识别、本地关键词检索与真实来源 ID、Qwen 结构化输出、SSE 流式响应和图片输入协议兼容性。

实验原型位于 `experiments/p1/`，测试位于 `tests/p1/`。用户原始资料始终保留在仓库外；聚合结果写入被 Git 忽略的 `tmp/p1-results.json`，不包含密钥或完整文档正文。

## 2. 解析结果

| 材料 | 结果 | 规模/类型 | 主要质量结论 |
| --- | --- | --- | --- |
| MyBatisPlus 事务规范 PDF | 57 页、63,481 字符、80 块 | `document / policy` | 文本覆盖率 100%，目录可信度高，适合作为主 Demo |
| RFC 6455 HTML | 159,488 字符、223 块、65 个标题 | `document / specification` | 旧式多 `<pre>` 页面可保留章节路径，适合作为公开回归材料 |
| AI Agents 教程 PDF | 316 页、576,976 字符、737 块 | `book / architecture` | 识别为大书；3 个低文本页，必须先选章节/主题再精读 |
| TypeScript 教程 PDF | 21 页、11,996 字符、21 块 | `document / tutorial` | 文本完整但无 PDF 目录，只能按页导航 |
| Java 部署教程 PDF | 11 页、4,338 字符、12 块 | `document / tutorial` | 文本覆盖率 64%，检测到 29 次图片绘制；必须显示截图/排版丢失告警 |
| Vue 3 Markdown | 43,314 字符、199 块、89 个标题 | `document / tutorial` | 检出 16 个去重图片引用，本地引用均存在；代码和标题结构可用 |

PDF 的 `imageCount` 是 PDF 绘制操作的近似计数，不等同于视觉语义识别结果。文本覆盖率使用“每页至少 100 个可提取字符”的 P1 规则，只用于告警，不代表排版完整度。

## 3. URL 安全验证

网关已实现并测试以下约束：仅 HTTP/HTTPS、禁止 URL 凭据、禁止 localhost，以及 IPv4/IPv6（含 IPv4-mapped IPv6）的回环、私网、链路本地、保留网段和云元数据目标；每次重定向重新校验，最多 3 次，15 秒超时，响应最大 10 MB，只允许约定内容类型。连接使用受控 DNS lookup，降低 DNS 重绑定绕过风险。

当前 Codex 开发网络把 `www.rfc-editor.org` 解析为基准测试保留地址 `198.18.0.44`。安全网关按设计拒绝了该地址。为验证固定的公开 RFC 解析器，P1 实验夹具使用系统网络代理对唯一硬编码的 RFC URL 进行了受限下载，没有放宽生产网关规则。

因此本阶段确认了“安全规则有效”和“RFC HTML 可解析”，但没有在当前网络完成任意公开 URL 经生产网关的端到端请求。P2 必须在本机普通网络或部署环境补测允许 URL、重定向到私网、超大响应和超时。

## 4. 检索与引用

- MyBatis 基准：5/5 通过。
- RFC 6455 基准：5/5 通过。
- 通过标准：期望证据词出现在 Top 5 真实来源块中，返回结果只包含解析器生成的来源 ID。

覆盖问题包括事务机制、HTTP/RPC、并发更新、消息一致性、无索引锁风险，以及 WebSocket 握手、掩码、Ping/Pong、关闭握手和 Origin 安全。

该结果证明关键词、英文标识符和中文 bigram 足够支撑固定 Demo，不证明对同义改写、跨章节推理或模糊概念的召回质量。首版继续使用本地检索；P3 增加“零结果/低分结果提示”，Embedding 不进入 v0.2 门槛。

## 5. Qwen 兼容性

| 能力 | 结果 | 最近一次实测 |
| --- | --- | --- |
| 结构化 JSON + Schema 校验 | 通过 | 约 12.9 秒；2,108 输入 tokens、2,218 输出 tokens，总计 4,326 |
| SSE 流式内容增量 | 通过 | 约 1.1 秒完成短响应 |
| OpenAI 风格图片输入 | 协议兼容 | 16×16 本地生成 PNG 请求约 1.3 秒成功，计入 66 image tokens |

结构化探针正确把 MyBatis 材料识别为 `policy / document` 并返回 8 个受 Schema 约束的章节。多次实验中该请求约 12–17 秒，且存在较多 reasoning tokens；P3 需要控制输入、输出上限并测首字节时间。当前 API 配置不包含价格信息，所以本阶段不能可靠计算人民币或美元成本。

图片探针只证明模型别名及网关接受图片消息，不证明截图 OCR、复杂表格、架构图或整页 PDF 的理解质量。v0.2 仍明确不支持视觉型文档；视觉能力只能作为后续独立评估项，不能绕过解析质量告警。

## 6. 已锁定的实现决定

1. 主 Demo 优先使用 MyBatis 规范，RFC 6455 作为公开、可复现的交叉回归材料。
2. 文档用途分类必须区分组织 `policy` 与公开 `specification`；规范内容表述为“该文档规定”，不得泛化成行业事实。
3. 超过 120 页或 200,000 字符的材料按 `book` 处理，先展示全局地图，再要求用户选定范围。
4. 低文本、无目录和高图片密度是显式产品状态，不静默生成看似完整的精读结果。
5. 首版保留本地检索与服务端来源 ID 校验，不引入向量数据库或 Embedding 依赖。
6. `qwen3.6-flash` 可作为文本主链路基线；视觉不纳入首版承诺。

## 7. 风险与 P2/P3 动作

- P2：在实际运行网络完成 URL 网关端到端测试，不能把 P1 固定 URL 夹具带入产品路径。
- P2：统一文件大小、提取字符上限、错误码和解析质量字段；原二进制仅在解析期间存在。
- P3：结构化请求增加输出上限、中文输出约束、超时和一次受控修复；记录供应商返回的 token 用量。
- P3：检索设置最低相关度和证据不足状态，并用非原词改写问题扩充回归集。
- P6：确认供应商价格/预算、公开访问限流和日总量上限。
- 安全：用户提供的截图和 CSV 曾暴露完整 API key。虽然仓库中的 `.env.local` 权限为 `0600` 且被 Git 忽略，仍应在 P2 开发前或最迟公开部署前轮换该 key。
- 依赖：P1 审计发现旧版 `pdfjs-dist` 存在恶意 PDF JavaScript 执行公告，已升级到 `6.3.289` 并重新验证全部材料；最终 `npm audit --omit=dev` 为 0 个已知漏洞。

## 8. 复现

```bash
npm install
npm run config:import -- /absolute/path/to/api-config.csv
npm run typecheck
npm test
npm run p1
```

`npm run p1` 会使用 `P1_VAULT_PATH` 指向的仓库外资料，并产生脱敏聚合结果。正式验证结果：TypeScript 静态检查通过，6 个测试文件共 25 项测试通过，完整 P1 实验退出码为 0。升级 PDF 依赖后又运行了完整解析/检索回归，10 个检索基准仍全部通过。
