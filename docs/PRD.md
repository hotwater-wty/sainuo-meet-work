# 技术文档精读助手 PRD

- 版本：`v0.2`
- 状态：P2–P5 已实现，P6–P7 待执行
- 目标读者：产品设计者、开发者、面试评审者
- 日期：2026-09-01

## 1. 产品定义

用户导入一份技术规范或架构文档，选择阅读目标和熟悉程度。系统生成文档地图与 3–6 个精读阶段，逐阶段解释机制、约束和概念关系，提供原文引用，并将用户确认过的阶段草稿累积为 Markdown 精读笔记。

## 2. 目标用户

首版面向需要理解陌生技术原理的软件开发者，尤其适合：

- 第一次阅读 RFC、协议规范或系统架构文档。
- 需要在实现或评审前快速建立正确概念模型。
- 希望保留术语、规则、边界和出处，而不是只看概括性摘要。

首版不面向论文研究、通用课程学习、客服知识库或企业文档管理。

## 3. 核心价值

1. **知道怎么读**：根据目标和基础生成阅读顺序及理由。
2. **知道为何如此**：围绕机制链路、约束和例外解释原文。
3. **知道依据在哪**：回答和笔记都能定位到真实来源。
4. **保留有效理解**：只有用户确认的内容进入最终笔记。

## 4. 首版目标

- 新用户在 3 分钟内导入文档、设置阅读画像并看到文档地图。
- 同一文档在不同阅读目标下生成可解释的不同路线。
- 完成至少一个“解释 → 检查 → 笔记确认”的精读阶段。
- 所有来源性陈述使用可定位引用，不伪造页码或章节。
- 最终笔记可下载为 Markdown。
- 提供公开 HTTPS Web Demo 和预置回归材料。

## 5. 核心流程

1. 用户上传文件、输入公开 URL 或选择预置材料。
2. 系统校验、解析并展示标题、来源、页数/章节和解析告警。
3. 用户选择阅读目标、熟悉程度，并可填写关注点。
4. 系统生成文档地图、前置知识、术语和 3–6 阶段路线。
5. 用户进入一个阶段，查看流式讲解、来源引用和检查问题。
6. 用户回答、追问或要求换一种解释。
7. 系统产生本阶段笔记草稿。
8. 用户编辑并接受，或跳过草稿，然后进入下一阶段。
9. 用户随时打开引用抽屉核对来源，最终导出 Markdown。

## 6. 功能需求

### FR-01 匿名临时会话

- 首次访问创建不可预测的匿名会话，使用 HttpOnly、SameSite Cookie 识别。
- 最后活动 2 小时后会话过期；服务重启后允许丢失。
- 一个会话只允许一份活动文档，替换前必须确认。
- 页面明确说明临时保存边界。

### FR-02 文件导入

- 支持带文本层的 PDF、Markdown、TXT 和 HTML。
- 单文件最大 10 MB，提取文本最大 500,000 字符。
- 校验扩展名、MIME、大小和空内容。
- PDF 保留页码；Markdown/HTML 保留标题路径；代码块尽量保持原文。
- 不支持 OCR；扫描 PDF 或正文过少时给出明确提示。

### FR-03 URL 导入

- 仅接受用户明确提交的公开 HTTP/HTTPS URL。
- 支持静态 HTML、PDF、Markdown 和纯文本，最多 3 次重定向，15 秒超时，响应最大 10 MB。
- 拒绝 localhost、私网、链路本地地址、带用户名密码的 URL 和其他协议。
- 记录最终 URL、页面标题和抓取时间，不自动刷新或抓取站内其他页面。
- 动态页面无法获得正文时提示改用文件导入。

### FR-04 文档分类与解析质量

- 系统将文档用途分类为 `specification`（公开规范）、`policy`（组织约束）、`tutorial`（教程）或 `architecture`（架构设计），并允许用户覆盖自动判断。
- 系统将文档规模分类为 `document` 或 `book`。超过 120 页或 200,000 字符时默认为 `book`。
- `document` 可直接生成全文 3–6 阶段路线；`book` 必须先生成全局地图，再由用户选择章节或主题范围，不能把全书强行压缩为 3–6 个阶段。
- 导入完成后展示解析质量报告：文本覆盖率、低文本页、图片密度、目录可信度、代码块/表格/缺失资源告警。
- 约束型文档中的规定必须表述为“该文档规定”，不能自动泛化为行业通用事实。

### FR-05 阅读画像

阅读目标为：

- `overview`：快速建立全局认知。
- `mechanism`：深入理解机制与约束。
- `implementation`：为实现或技术评审做准备。

熟悉程度为：

- `new`：初次接触。
- `basic`：了解基础概念。
- `experienced`：已有实践经验。

用户可补充最多 500 字的关注点。未选择目标和程度前不能生成路线。

### FR-06 文档地图

系统输出结构化文档地图：用途、适用范围、核心问题、主要结论、章节结构、前置知识、核心术语、解析限制及建议路线。

路线包含 3–6 个阶段，每阶段说明标题、目标、涉及章节、前置阶段和推荐理由。系统不再使用简单/复杂二分类。

### FR-07 阶段精读

- 每次只推进一个阶段。
- 内容包含阶段目标、核心机制、概念关系、示例、约束/例外、常见误解和原文引用。
- 讲解默认中文，保留英文术语、RFC 规范关键词和代码原文。
- 阶段末提供一个理解检查问题。
- 用户可回答、追问、请求换一种解释或结束本阶段。

### FR-08 检索与引用

- 文档按标题、页码和代码边界切分，文本块带唯一来源 ID。
- 本地检索结合章节匹配、英文标识符、中文 bigram 和关键词相关度。
- 只有本轮提供给模型的来源 ID 才能出现在回答中。
- 点击引用打开来源抽屉，显示片段、页码/标题路径、原 URL 和抓取时间。
- 无有效证据时显示“文档中未找到足够依据”。

### FR-09 阶段笔记确认

- 阶段完成后生成结构化笔记草稿。
- 草稿加入最终笔记前可编辑、接受或跳过。
- 未接受草稿不写入最终笔记，也不因重试重复加入。
- 接受后标记该阶段完成；用户仍可返回查看，但首版不提供完整笔记编辑器。

### FR-10 Markdown 导出

导出内容固定包含：来源元数据、阅读画像、一分钟概览、术语表、机制/架构链路、关键规则与约束、示例、陷阱、待追问项和引用。

文件名由文档标题安全生成；服务端设置 Markdown MIME 与下载头，不接受客户端提供的服务器路径。

### FR-11 无文档状态

- 未导入文档时不开放通用模型聊天。
- 用户只能选择预置材料、上传文件或输入 URL。
- 首版不主动搜索网页，不使用模型参数生成伪来源材料。

### FR-12 错误与恢复

- 模型或网络失败时保留用户输入并允许重试。
- 流式讲解中断时不推进阶段、不生成笔记草稿。
- URL、解析、检索和引用失败分别显示可操作提示。
- 会话过期时提示重新导入，不假装恢复已丢失内容。

## 7. 非功能需求

- 桌面工作区优先，390 px 移动视口无横向溢出和控件遮挡。
- 文档地图在正常模型和网络条件下目标 30 秒内返回；流式讲解目标 8 秒内出现首段内容。
- 服务端不记录完整文档、完整提示词或密钥。
- 公开 Demo 对上传、URL 导入和模型请求进行按 IP/会话限流。
- 页面披露文档会被发送给模型供应商，不应上传敏感或无权处理的资料。
- AI 输出是阅读辅助，不能替代原规范和技术评审。

## 8. 验收标准

1. 四种文件格式和允许的公开 URL 均能创建统一来源记录。
2. 扫描 PDF、动态空页面、私网 URL、超限和非法类型被正确拒绝。
3. 不同阅读画像对同一文档产生不同且有理由的路线。
4. 一个阶段能够完成讲解、引用定位、检查问题和笔记草稿。
5. 流式中断或模型失败不会错误推进状态。
6. 用户修改、接受和跳过草稿后，导出内容与操作一致。
7. 所有展示引用能定位到实际传入模型的来源片段。
8. 无文档时不能绕过入口进入通用聊天。
9. 使用获准的 MyBatis 规范或 RFC 6455 完成主 Demo，并用另一份材料交叉回归。
10. 316 页的大型教程被识别为 `book`，先选择范围再生成局部路线；截图型文档显示低文本/图片告警。

## 9. 不纳入首版

- 主动联网搜索、跨页面爬取和自动同步。
- OCR、图片/图表理解、公式结构恢复。
- 代码执行、沙箱和仓库分析。
- 多文档对比、长期知识库和跨会话记忆。
- 账号体系、多人协作、生产级持久化。
- 完整 Markdown 编辑器、Skill 市场和多 Agent。
- 对 DeepTutor 或其他竞品的源码复用。

## 10. 成功指标

- 首次文档地图完成时间不超过 3 分钟。
- 固定回归问题的引用可定位率为 100%。
- 5 次主流程手工测试至少 4 次无阻塞完成。
- 未接受草稿进入导出的次数为 0。
- 测试者完成第一阶段后能说明文档核心机制及一个关键约束。

## 11. 外部依赖

- 用户已提供允许测试和展示的混合格式资料；其中 MyBatis 规范允许用于本项目。
- 开发阶段使用用户提供的 OpenAI-compatible Qwen API，默认模型为 `qwen3.6-flash`，模型切换仅限 Qwen 系列。
- 用户在部署阶段确认托管平台、公开期限和访问保护。
