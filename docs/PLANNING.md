# 滚动开发计划

- 版本：`v0.2`
- 当前阶段：`P2–P5 本地完成验收已通过（本次目标完成）`
- 最终目标：公开在线的技术文档精读助手 Demo + 5–10 页交付材料
- 状态枚举：`待开始`、`进行中`、`受阻`、`已完成`

## 1. 使用规则

- 同一时间只能有一个阶段处于“进行中”。
- 开始阶段前读取 `PRD.md`、`ARCHITECTURE.md` 和本文件对应门槛。
- 阶段内发现范围、数据、安全、成本或接口需要变化时，先停止实现并更新设计基线。
- 阶段完成必须同时满足交付物、自动化/手工验证和业务交接，不以“代码已写”代替完成。
- 每次阶段切换同步更新本文件的状态、`CURRENT.md` 和决策记录。
- 不把后续阶段的功能提前塞入当前阶段；必要工作写入滚动待办。

## 2. 不可偏离的产品约束

1. 没有文档，不开放通用聊天。
2. 只读取用户上传内容或用户明确提供的公开 URL，不主动搜索。
3. 阅读路线由目标和熟悉程度驱动，不恢复简单/复杂二分类。
4. 只有真实来源片段可以成为引用。
5. 阶段笔记必须由用户编辑/确认或跳过，不能自动写入最终成果。
6. 首版只处理单文档、匿名临时会话，不扩展为知识库或 Agent 平台。

## 3. 阶段计划

### P0 设计基线替换

- 状态：已完成
- 目标：用技术文档精读方向完整替换旧课程学习方案。
- 交付物：调研、PRD、可行性、技术选型、架构和滚动计划 `v0.2`。
- 退出标准：旧方向不再作为任何文档的当前计划；根目录状态与新基线一致。

### P1 技术可行性验证

- 状态：已完成
- 目标：在创建完整 UI 前验证最大风险。
- 工作：
  - 对用户混合格式资料和 RFC 6455 运行 PDF/MD/TXT/HTML 解析实验。
  - 验证公开 URL 导入、正文提取和 SSRF 防护方案。
  - 验证 `qwen3.6-flash` 结构化文档地图、SSE 流式响应和视觉输入兼容性。
  - 用 MyBatis 规范与 RFC 6455 的基准问题评估本地检索和引用定位。
  - 验证文档用途/规模分类和解析质量报告，确保大型教程与截图型文档不会被错误当作普通文本处理。
- 退出标准：形成兼容性报告；至少一份 PDF 和一份 HTML/URL 可稳定解析；模型输出可校验；所有基准引用能回到来源。
- 阶段交接重点：支持与不支持的文档特征、模型费用/延迟、本地检索局限、是否需要调整范围。
- 实际结果：见 `docs/reports/P1_VALIDATION.md`；6 类材料解析完成，MyBatis/RFC 基准 10/10 通过，Qwen 结构化、SSE 和图片协议探针通过。开发网络的保留地址映射导致生产 URL 网关端到端测试顺延到 P2。

### P2 应用基础与来源导入

- 状态：已完成
- 目标：用户可以安全创建临时会话并导入一份文档。
- 工作：Next.js 工程、会话 TTL、文件上传、URL 网关、统一来源模型、解析状态和错误反馈。
- 退出标准：四类测试文件和允许 URL 通过；非法类型、扫描 PDF、私网 URL、超限和动态空页面按 PRD 处理；刷新后会话仍可在 TTL 内访问。
- 阶段交接重点：文档去向、保存时长、URL 网络边界、错误与清理行为。
- 实际结果：见 `docs/reports/P2_HANDOFF.md`；本地工作区、匿名 TTL 会话、四类文件与受控 URL 管线完成，真实 MyBatis HTTP 上传通过。

### P3 文档地图、路线与检索

- 状态：已完成
- 目标：根据阅读画像生成可解释的文档地图和 3–6 阶段路线。
- 工作：阅读画像、分块索引、结构摘要、Qwen 结构化输出、引用映射和来源抽屉。
- 退出标准：三种目标和三种熟悉程度均可提交；至少两组画像产生可说明的路线差异；引用只来自有效来源 ID。
- 阶段交接重点：路线如何形成、模型与规则各自负责什么、引用如何防伪、何时提示证据不足。
- 实际结果：见 `docs/reports/P3_HANDOFF.md`；画像驱动地图、3–6 阶段路线、范围编号白名单和来源抽屉完成，真实路线延迟优化到 11 秒。

### P4 阶段精读工作流

- 状态：已完成
- 目标：完成一个可交互、可恢复的精读阶段。
- 工作：阶段状态机、SSE 讲解、检查问题、追问、换一种解释和流式失败恢复。
- 退出标准：完整阶段可推进；只能有一个活动阶段；SSE 中断不污染状态；引用抽屉可定位本轮来源。
- 阶段交接重点：阶段业务状态、何时提交结果、失败后的用户体验和模型幻觉控制。
- 实际结果：见 `docs/reports/P4_HANDOFF.md`；SSE 首事件 0.79 秒、完整响应 7.61 秒，中断原子性、阶段互斥和引用过滤均通过。

### P5 确认式笔记与导出

- 状态：已完成
- 目标：把用户认可的理解沉淀为可下载成果。
- 工作：草稿生成、编辑、接受/跳过、幂等处理、笔记汇总和 Markdown 下载。
- 退出标准：编辑内容正确保存；重复接受不重复写入；跳过内容不出现在导出；文件名和下载头安全。
- 阶段交接重点：AI 草稿与用户成果的所有权边界、写入条件、可回退范围和导出结构。
- 实际结果：见 `docs/reports/P5_HANDOFF.md`；草稿编辑、接受/跳过、幂等决议和安全 Markdown 导出完成，真实主流程通过。

### P2–P5 本地完成审计

- 状态：已完成
- 目标：用当前代码在真实浏览器中完成 P2–P5 主流程，并核对响应式布局、安全配置、自动化和文档一致性。
- 实际结果：见 `docs/reports/LOCAL_ACCEPTANCE.md`；真实 MyBatis 上传、4 阶段路线、来源抽屉、SSE 讲解、笔记编辑接受、Markdown 下载和刷新恢复通过。
- 验收修正：本地 `127.0.0.1` 同源判断、刷新后的阶段定位、组织规范来源外事实约束。
- 最终门槛：16 个测试文件、59 项测试，TypeScript、生产构建、依赖审计和 390 px 移动布局全部通过。

### P5.5 体验稳定化设计与实现

- 状态：进行中（导航与左侧栏已完成，消息渲染与右侧精读抽屉待实现）
- 目标：让生成结果可读，并让阶段精读成为稳定的对话工作区。
- 工作：完整回答统一 Markdown 渲染和引用入口；桌面右侧可收起精读抽屉；移动端响应式抽屉；阶段生成、失败、完成和笔记状态提示。
- 退出标准：标题/列表/代码块/表格可读；合法引用可定位；抽屉开关不丢阶段状态；390 px 无遮挡；流式中断不写入正式消息或笔记；导入到导出的主流程经用户复验。
- 阶段交接重点：解释消息临时态与正式态、抽屉可见性与阶段状态的区别，以及引用交互如何保持服务端来源约束。

## 5. 阶段交接模板

每完成一个阶段，向用户提供以下内容：

1. 本阶段解决的业务问题。
2. 已锁定的业务约定和状态变化。
3. 用户文档、模型和系统之间的数据流。
4. 关键技术取舍及其业务影响。
5. 已知限制、失败表现和降级方式。
6. 自动化与手工验证结果及复现方法。
7. 对 PRD/架构/计划的任何修订。
8. 下一阶段依赖和需要用户确认的事项。
