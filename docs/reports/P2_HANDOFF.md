## 解决的业务问题

用户现在可以在本地 Web 工作区创建匿名临时会话，并通过文件或明确 URL 导入一份技术文档。导入后系统展示用途、规模、页数、来源块和解析质量，不在无文档状态开放聊天。

## 已锁定约定

- 会话以 HttpOnly、SameSite Cookie 识别，最后活动 2 小时后清理。
- 一个会话一份活动来源；替换需要确认，成功替换会清空画像、路线和笔记。
- 原始文件只在请求内存中存在，服务端只保留解析块与元数据。
- 完整解析用于规模/质量判断，索引最多保留 500,000 字符并告警。
- Markdown 单文件上传中的相对图片不会读取客户端目录，而是显示缺失资源。
- URL 网关不因当前开发网络的特殊 DNS 映射放宽私网/保留网段规则。

## 数据流与控制点

```text
浏览器 -> 会话 Cookie -> 文件/URL 校验 -> 格式解析 -> 字符上限 -> TTL Store
```

来源解析成功前不会替换已有来源。Route Handler 只返回脱敏会话视图，完整来源文本不发送给浏览器。URL 每次重定向重新校验目标，HTML 不执行脚本和子资源。

## 验证结果

- TypeScript 检查通过。
- 9 个测试文件、38 项测试通过。
- Next.js 生产构建通过。
- 真实 HTTP 上传 MyBatis PDF：57 页、80 个来源块、100% 文本覆盖，分类为 `policy / document`。
- 私网 URL、伪造 PDF、非法扩展名、未确认替换、会话过期和请求频率均有自动化覆盖。

## 限制与降级

- 当前环境不能完成公共 URL 允许地址的生产网关端到端测试；安全拒绝和固定 RFC 解析已经分别验证，允许地址留待普通或部署网络。
- OCR、公式和图片语义不支持；低文本 PDF 显示告警。
- 进程内会话在开发服务器重启后丢失，这是 v0.2 已接受边界。

## P3 依赖
