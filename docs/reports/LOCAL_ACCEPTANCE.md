## 1. 真实主流程

本次使用获准展示的 `MyBatisPlus数据库事务代码规范.pdf` 和真实 `qwen3.6-flash` API，在浏览器中完成以下流程：

1. 首次访问创建匿名 HttpOnly Cookie 会话，无文档时只显示来源导入入口。
2. 上传 57 页 PDF，得到 `policy / document` 分类、80 个来源块和 100% 文本覆盖率。
3. 选择“准备实现评审 / 了解基础”，关注事务边界、异常处理和代码审查要求。
4. 生成文档地图和 4 阶段路线，浏览器观察时间在 30 秒目标内。
5. 打开首阶段来源抽屉，引用可回到第 1、25、37、50、57 页的真实片段。
6. 启动阶段并观察 SSE 增量文本；完整结束后才显示保存的助手消息、4 条有效来源和理解检查。
7. 结束阶段后状态停在 `awaiting_note`，不会直接把 AI 内容写入成果。
8. 生成 1,426 字符草稿，人工改写为 219 字符的核对版后接受；首阶段变为 `completed`。
9. 下载 Markdown；下载入口只有在至少一份笔记被接受后出现。
10. 刷新页面后文档、路线、讲解和人工编辑内容均恢复，并自动落到第 2 个待开始阶段。

## 3. 验收中发现并修复

### 本地同源误判

现象：使用 `127.0.0.1` 打开页面时，Next.js 的 URL 原点被规范化为 `localhost`，首次会话请求错误返回“请求来源不受信任”。

处理：同源校验改为比较浏览器 `Origin` 与真实 HTTP `Host` 和协议，不放宽跨主机请求。增加 `127.0.0.1` 接受、主机不匹配拒绝和无 `Origin` 三类测试。

### 刷新后回到已完成阶段

现象：没有活动阶段时，刷新总是选择路线第 1 项，即使该阶段已经完成。

处理：选择规则改为“活动/待确认 → 第一个待开始 → 最后一个已完成”，并增加独立状态测试。

### 组织规范的模型背景混入

现象：一次真实讲解使用了合法引用 ID，但加入了来源片段未明确提供的 Spring AOP 背景说明。

处理：组织规范提示同时要求“使用该文档规定的措辞”和“不得补充来源片段之外的文档事实”。合法 ID 仍不能证明逐句语义蕴含，扩大语义评测保留在开放问题中。

- 当前网络不能完成正常公开 URL 经生产网关的允许路径端到端测试。

- 引用 ID 防伪不能替代逐句语义支持度评测。
- OCR、复杂表格、公式和图表语义不在首版支持范围。
- 公开费用、限流、访问保护、Docker 和托管验证属于 P6。
