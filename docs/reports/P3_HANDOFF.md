# P3 阶段交接：文档地图、路线与检索

- 日期：2026-09-02
- 状态：已完成
- 下一阶段：P4 分阶段精读工作流

## 解决的业务问题

用户导入文档后可以设置阅读目标、熟悉程度和关注点，获得中文文档地图与 3–6 阶段路线。每个阶段可在来源抽屉查看服务端本地检索到的真实片段；大书未选择范围时不能生成路线。

## 已锁定约定

- 模型负责提炼和排序，服务端负责分类、解析限制、阶段 ID 和来源可信性。
- 模型只返回 `SC01` 等短范围编号，服务端映射回真实目录/页段；未知编号不能保存。
- 结构化输出校验失败只修复一次，二次失败不污染现有会话。
- 地图只发送目录和 8 个均匀代表片段，不发送完整索引。
- 文档地图任务默认关闭 Qwen thinking；环境变量可恢复，但必须重新评估延迟与质量。

## 数据流

```text
来源块 + 阅读画像
  -> 目录/范围编号 + 代表片段
  -> Qwen JSON
  -> Zod + 范围白名单
  -> 服务端真实标题映射
  -> ReadingPlan

阶段标题/目标
  -> MiniSearch
  -> 真实 SourceChunk
  -> Citation（服务端标签、页码/标题、摘录）
```

## 真实模型调整

首次实现要求模型逐字复述长目录字符串，连续两次校验失败；改成服务端范围编号后，剩余失败来自 Qwen 稳定地把术语表返回对象而非数组。服务端增加等价形态归一化后通过。有效路线在 thinking 开启时耗时 59 秒；关闭 thinking、代表片段降至 8 个后为 11 秒，低于 30 秒目标。

## 验证结果

- 11 个测试文件、43 项测试通过（增加兼容测试后全套数量将在最终回归更新）。
- TypeScript 与 Next.js 生产构建通过。
- 真实 `mechanism/basic`：5 阶段、5 条结论、10 个术语，首阶段 5 条真实引用。
- 真实 `implementation/experienced`：4 阶段、6 个术语，路线耗时 11 秒。
- 引用预览返回的块 ID 全部来自当前来源；空查询返回证据不足。

## 限制与 P4 依赖

- 本地检索目前以关键词/标识符为主，同义改写召回仍可能偏弱。
- thinking 关闭后的路线质量只经过两组画像验证，需在最终主流程回归继续观察。
- P4 必须只把本轮检索片段交给模型，并在流式完整结束后提交消息和阶段状态。
