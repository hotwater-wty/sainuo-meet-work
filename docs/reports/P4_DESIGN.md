# P4 实施设计

- 日期：2026-09-02
- 状态：已完成
- 目标：完成可流式交互、失败不污染状态的单阶段精读

## 阶段动作

| 动作 | 允许状态 | 用户输入 | 成功后的状态 |
| --- | --- | --- | --- |
| `start` | `pending` | 无 | `active` |
| `follow_up` | `active` | 必填 | 保持 `active` |
| `rephrase` | `active` | 可选 | 保持 `active` |
| `answer_check` | `active` | 必填 | 保持 `active` |
| `finish` | `active` 且已有讲解 | 无 | `awaiting_note` |

同一会话同时只能有一个流式请求和一个活动阶段。`awaiting_note` 阶段必须先处理笔记，不能开始下一阶段。

## 流式原子性

```text
校验状态 -> 设置临时流锁 -> 检索候选来源 -> 上游 SSE
  -> 浏览器 delta（未持久化）
  -> 完整结束 -> 过滤引用 ID -> 原子提交消息/状态 -> complete 事件

上游错误/中断 -> 清除流锁 -> error 事件 -> 不写消息与阶段状态
```

## 提示与引用

- 文档片段始终放在明确的数据边界内，不能覆盖系统指令。
- 模型只能使用候选 `[Sx]` 引用标记。
- 完整输出后服务端提取标记，未知 ID 丢弃；没有有效标记则显示证据不足。
- 约束型文档继续使用“该文档规定”表述。
- 理解检查问题由阶段标题和目标生成稳定模板，避免第二次模型调用。

## 验证门槛

- start、追问、换一种解释和回答检查均可流式返回。
- 流完成后才出现消息和 `active` 状态。
- 模型在第一个或中间 token 后失败时，消息数和阶段状态不变。
- 未知引用不会进入浏览器会话视图。
- 有活动/待笔记阶段时不能开始其他阶段。
- 完成流式讲解后可进入 `awaiting_note`，但不能直接 `completed`。
