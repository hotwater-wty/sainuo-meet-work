# P5 阶段交接：确认式笔记与导出

- 日期：2026-09-02
- 状态：已完成
- 当前边界：本地产品闭环完成，进入范围验收；P6/P7 不在本次目标

## 解决的业务问题

用户结束精读阶段后可以生成 AI 草稿、直接编辑、接受或跳过。只有接受后的文本成为最终成果，并可下载固定结构的 Markdown 笔记。

## 已锁定约定

- 一个阶段一个草稿；重复生成返回同一 ID，不增加模型调用。
- 模型返回结构化要点，服务端渲染固定 Markdown，用户编辑的是实际待保存文本。
- 接受和跳过都是最终决议；相同动作重试幂等，冲突动作返回 409。
- 两种决议都会完成阶段，但只有 `accepted` 进入导出。
- 导出引用来自对应阶段已保存的真实 Citation，不从草稿文本反向解析。
- 下载中和危险原生 HTML 与 `javascript:` 链接，文件名由服务端生成。

## 数据流

```text
awaiting_note 阶段 + 已保存消息/引用
  -> Qwen 笔记要点 JSON
  -> 服务端固定 Markdown 草稿
  -> 用户编辑
  -> accept / skip 幂等决议
  -> completed
  -> accepted 草稿汇总下载
```

## 验证结果

- 14 个测试文件、53 项测试通过。
- TypeScript 与 Next.js 生产构建通过。
- 真实草稿 1,507 字符，初始状态 `pending`。
- 首次接受后阶段 `completed`、笔记 `accepted`、数量 1；重复接受仍为数量 1。
- 接受后再跳过返回 `DRAFT_ALREADY_RESOLVED`。
- 导出文件 6,018 字节，包含来源、画像、概览、术语、确认笔记、引用索引和用户追加内容。
- 下载头为 `text/markdown`、安全 ASCII 回退文件名、UTF-8 文件名与 `nosniff`。

## 已知限制

- 草稿生成仍依赖模型服务；失败时阶段保持 `awaiting_note` 并允许重试。
- 首版不提供跨阶段全文笔记编辑器；只能在接受前编辑单阶段草稿。
- 会话过期或服务重启会丢失尚未下载的成果，这是进程内 TTL 方案的既定边界。
