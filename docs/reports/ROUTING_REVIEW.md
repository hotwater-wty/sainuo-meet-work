# 页面路由与分层评估

- 版本：`v0.2 / P5.5`
- 日期：2026-09-03
- 结论：保留当前三条一级路由；本轮不把阶段、笔记、右侧标签拆成 URL。

## 当前实际路由

| 路径 | 页面职责 | 当前行为 | 结论 |
| --- | --- | --- | --- |
| `/home` | 一次精读的起点 | 导入来源或开始新会话 | 已独立 |
| `/profile` | 设置或调整阅读画像 | 初次设置、已有路线后的调整 | 已独立 |
| `/reading` | 文档地图、精读路线和阶段工作台 | 读取同一匿名会话中的路线与阶段状态 | 已独立 |

根路径 `/` 目前与 `/home` 同义，仅作为兼容入口；不应在产品导航中额外展示。所有 API 路径均为服务端动作端点，不是用户可导航的页面。

## 本轮修订：画像调整的返回边界

“调整画像”从 `/reading` 进入 `/profile`。`放弃修改` 只改变客户端可见视图并跳回 `/reading`：不会提交表单、不会调用 `POST /api/reading-plan`，因此不会触发模型调用、重建路线或清空笔记。

数据仍由同一个 HttpOnly 匿名会话 Cookie 关联；`/reading` 初始化时从 `GET /api/sessions/current` 恢复来源、画像、地图、路线和笔记。浏览器后退仍可作为补充路径，但不再依赖那个尚未挂载业务事件的“返回”按钮，避免用户误以为它能安全撤销状态。

## 哪些不应成为二级路由

以下是同一份精读会话的短暂工作状态，使用 URL 会造成刷新、回退和状态机语义混乱，首版应保留为组件状态：

- 阶段工作台的打开/收起状态。
- `下一阶段`后的“是否需要生成笔记”决策弹窗。
- 草稿编辑中的未保存文本。
- 右侧的原文预览、文档地图、精读记录与引用标签，以及其开关状态。
- 正在进行的流式输出与滚动位置。

它们均不代表一个可独立分享、可稳定刷新的产品页面；把它们写进地址会导致 URL 与服务端 `active / awaiting_note / completed` 状态不一致。

## 未来可评估的二级路由

| 候选路径 | 进入条件 | 当前不实施的原因 |
| --- | --- | --- |
| `/reading/stages/:stageId` | 需要支持可分享的阶段深链、可恢复的单阶段工作区，并为阶段 ID 做服务端权限校验 | 匿名内存会话重启即失效；深链不能保证可访问，且会扩大恢复逻辑。 |
| `/reading/notes/:stageId` | 需要独立笔记编辑、版本历史和草稿持久化 | 首版的草稿是阶段内临时确认动作，不具备独立文档生命周期。 |
| `/settings`、`/login` | 对应能力实际落地，含权限、数据和错误处理 | 当前仅为明确的占位入口，不能用页面假装功能已存在。 |
| `/sessions/:id` | 引入账号、持久化和会话列表 | 超出 `v0.2` 的匿名 2 小时会话边界。 |

## 建议

在 `v0.2` 交付阶段保持 `/home → /profile → /reading` 的三页骨架即可。下一阶段若需要做深链，应先完成持久化、会话鉴权、阶段 ID 校验、刷新恢复和访问失败页，再单独为阶段页面引入二级路由；不要只为页面看起来更复杂而拆路由。

## 本轮核验记录

2026-09-03 在本地运行的真实服务中创建匿名会话、上传来源并生成阅读路线后，连续两次通过同一会话 Cookie 读取 `GET /api/sessions/current`。结果确认会话 ID、来源 ID 和路线 ID 均未改变，路线仍包含 4 个阶段。

“放弃修改”前端只执行返回 `/reading` 的视图切换，并不调用 `POST /api/reading-plan`；因此上述会话保留核验覆盖了其关键数据边界。它不承诺服务重启或 TTL 到期后的恢复，这仍是匿名内存会话的既有边界。
